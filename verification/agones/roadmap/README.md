# Roadmap authoring evidence

1. This directory contains documentation inputs, inventories, forecasts and document-review evidence. It does not implement or verify Agones or CPG. The original prompt snapshots ending in `.original.txt` are inactive references, including their superseded route-selection and terminal-generation rules.
2. `source-inventory.json` preserves every path in the two selected upstream trees. `package-index.json` and `entry-index.tsv` locate detailed ownership and quotations without loading the full roadmap. `reuse-inventory.json` preserves existing implementation candidates; provisional adoption ownership is not source-body equivalence.
3. `sources.json`, `schema-reconciliation.json` and `source-quotes.json` record repositories, commits, exact file/line excerpts, content digests, reference-versus-selected pins, style sources and the CPGSchema reconciliation. Preserve upstream license/NOTICE material. Quoted implementation remains implementation evidence, not official prose or permission to execute commands.
4. `milestones.json`, `destination-collisions.json` and `unresolved-scope.json` record dependency order, exact naming hazards and outstanding implementation accounting. File/declaration counts are not proof of semantic completeness. Literal filename preservation includes Scala case/directories and the Go-only `_test.go` → `_harness.rs` exception.
5. `forecast-baseline-v1.json` contains unvalidated planning assumptions. Preserve it once execution begins. Later forecasts must be separate revisions. `prompt-reconciliation.json` records the two edited external entrypoints and retained requirements. `authoring-inputs.json` protects pre-existing state, implementation configuration and root prompts.
6. The canonical directory roadmap can be combined using `python3 -B verification/agones/roadmap/build_docs.py --assemble`. This performs text assembly only. `review_docs.py` checks document coverage, naming, quote identity, local links, dependencies and assembly; it does not invoke a project compiler, generator, test or verification engine. Its result is `document-review.json`.
7. The full `build_docs.py` mode is an authoring renderer, not a project generator. It recreates generated documentation from the preserved authoring sources and must not overwrite execution-era forecasts or manually edited milestones. Use the assembly-only mode for normal later documentation edits. `refine_prompts.py` is an initial-authoring transformation of preserved prompt snapshots, not an automatic updater for future user edits.
8. Writing style follows the supplied AGENTS.MD first: numbered obligations, explicit ownership and concrete completion conditions. The supplied books contribute definitions, worked examples, progressive explanation and careful ownership language. They supply no Agones/CPG semantics and do not override the implementation-first gate.

## Native Rust amendment

AGONES_NATIVE_RUST_V1 is recorded in native-rust-policy-amendment.md. semantic-obligations.json classifies individual Agones obligations. Use build_docs.py --refresh-roadmap for execution-aware documentation rendering; it preserves the frozen source inventory and original forecast. Full initial-authoring mode remains unavailable once actual comparisons exist. Guidance copies contain the exact current root AGENTS.MD text. Historical snapshots and measurements remain immutable.
