# Agones-rs continuation tools

The native Codex Goal controls continuation. `AGONES_RS_STATE.json` indexes
content-bound implementation gates and evidence; it is not a replacement Goal
or scheduler. `AGONES_RS_HANDOFF.md` is generated by `checkpoint.py`.

Use Python with the exact dependencies in `state-requirements.txt`. This host's
bundled Python is
`/home/astral/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3`.
Run `checkpoint.py check` to check the model/schema, original census, current
implementation gate, retained logs, and credited evidence bindings.

`inventory.py census` freezes the immutable default baseline. Do not rerun it to
adopt changed source or replace the migration scope. `guidance-check` verifies
inherited project instructions; `guidance-apply` adds only missing pointers and
preserves existing local/third-party instructions, including the vendored
OpenTelemetry guide. Tracked generated/vendor/documentation directories count.

`run.py <unique-id> [--quiet] [--cwd <repository-relative-directory>] <command...>`
records intent, source/tool bindings, process identity, complete output and exit
status. A run ID cannot be reused. `--quiet` retains the whole log while keeping
large model-checking output out of the conversation. Recover a live job using
the recorded process start identity before waiting, stopping or retrying it.

The focused Go extractor has its own pinned module in `extract/`. It refuses
missing/stale/unfinished implementation gates and changed original source.
Use `go -C build/scripts/agones-rs/extract run . <absolute-repository-root> <gate-path>`.
Its JSON output is typed source-test IR. The first feature has five supported
cases/17 assertions; one environment case/five assertions remains unsupported.
Unknown semantic calls fail closed, and repeated names keep distinct identities.

The production boolean parser is tested by one shared-domain Bolero/Kani harness:
`feature_bool_common_domain` in `crates/agones-core/tests/feature_bool_domain.rs`.
Run cargo-bolero 0.13.4 **built with `--no-default-features --features kani`**, from
`crates/agones-core`, using `cargo bolero test feature_bool_common_domain --engine kani`.
The selected CLI route is the real Bolero frontend invoking `cargo kani --tests
--harness feature_bool_common_domain`. This CLI version does not forward its
project/engine options to Kani; the working directory selects the core package,
and the harness attribute supplies unwind 8. Verify Cargo.lock is unchanged.

`summarize_bool_proof.py [run-id]` checks every individual Kani result, exact
harness count, all three claimed assertions, five required covers and the
Bolero valid-generator cover. Unreachable internal checks are retained and
never credited as source obligations. `check_bool_mutations.py` uses isolated
crate identities to confirm that lexical faults are rejected by source witnesses.

This bounded helper proof does not model-check the 17 original query/encoding
assertions, environment/CLI binding, async controllers or unbounded strings.
Keep those assurance categories and required `_2` architecture cells open.
